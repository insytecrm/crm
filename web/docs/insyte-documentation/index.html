Before you start

00How to read this

This is not a pitch deck. Sentences describe what the software actually does. Where the marketing site talks about scoring, voice campaigns, or social posts, and the code does not ship those yet, they are listed as not built yet.

There are three apps in one repository:

  • Marketing site — public landing, demo and trial forms, legal pages.
  • Platform — /platform for InSyte superadmins. Plans, channel partners, usage.
  • Tenant CRM — /{company}/… or a custom CRM domain. This is what a channel partner’s team uses every day. Public property pages live on the same tenant, or on a separate website domain.

Part 1

How it is built

Stack, architecture, tenancy, integrations, and the plan system that turns modules on and off.

Architecture

1.1What the system is

InSyte CRM is a multi-tenant Laravel application for real-estate channel partners. Each company is a tenant with its own database. The central database holds plans, tenants, and platform users.

LandingCentral domain
PlatformSuperadmin
Tenant CRMPath or CRM domain
MicrositesWebsite domain

Tenancy is implemented with Stancl Tenancy. Identification is by path (/acme/dashboard) or by a verified custom domain. Tenant databases, cache, files, and queues are isolated. A tenant can also attach two domain purposes: CRM (the app) and website (public property pages).

1.4How the code is organized

HTTP controllers stay thin. Work lives in Actions. List screens and KPIs live in Query objects. Validation lives in Form Requests. Statuses and plan keys are PHP enums.

FolderRole
app/ActionsOne job: create a lead, run an automation, complete OAuth, sync a sheet, run an AI turn
app/QueriesListings, dashboard KPIs, reports, team performance
app/Http/RequestsInput rules at the HTTP boundary
app/EnumsLead status, plan features, permissions, automation triggers
app/SupportAI client, Google Sheets client, Meta Graph client, plan access
app/Eventse.g. lead activity recorded → dispatch automations

Platform users and tenant users are both User models, but they log in through different routes and middleware. Superadmin is a platform gate. Tenant permissions are checked with permission: middleware and Blade <x-tenant.can>.

1.5Surfaces and tenancy

Custom domains: a tenant admin pastes a hostname, creates a CNAME to the InSyte target, then verifies. Purpose crm serves the CRM. Purpose website serves public project pages. Suspended tenants cannot use either surface.

1.7Plans as controls

Superadmins define plans. A plan has modules (features), optional packs (Basic / Advanced / Custom) on CRM, Reports, Automations, and InSyte AI, plus numeric limits.

Default planWhat it turns onExample limits
StarterCRM, properties, bookings, revenue, reports, teams, automations, inbox, WhatsApp, API + Sheets. No AI, no microsites.5 users, 2,000 leads, 0 AI messages / month
GrowthEverything in Starter plus InSyte AI (basic pack), microsites, custom domains, Facebook15 users, 10,000 leads, 1,000 AI messages / month
ProAll modules, advanced AI pack, all integration capabilities50 users, 50,000 leads, 10,000 AI messages / month

Limits that exist in code: users, leads, automations, automation runs / month, WhatsApp messages / month, AI messages / month, integrations, properties, teams, microsites.

Channel partner records (tenants) sit next to plans. Superadmins create a company, assign a plan, and inspect users, subscription, usage, integrations, and activity.

Part 2

What it does

Product overview, modules, the full feature list, why each piece exists, and the paths users follow.

Product

2.1Product overview

InSyte CRM is for people who sell property through a channel-partner business. The daily job is: take an enquiry, follow up, take a site visit, book a unit, and see commission.

Who uses it

RoleWhereTypical work
Sales executiveTenant CRMLeads, WhatsApp, follow-ups, site visits, tasks
Team lead / managerTenant CRMAssign leads, pipeline, team performance, reports
Tenant adminSettingsUsers, roles, domains, integrations, company profile
Platform superadmin/platformPlans, onboard partners, usage
Buyer (public)Property pageView a project and send an enquiry

Lead pipeline

New → Contacted → Qualified → Follow-up → Site visit → Negotiation → Converted or Lost

Converted and Lost are closed states. They are not chosen from the normal status dropdown; they are set by Close or Mark lost actions.

Operating loop

StepIn the product
CaptureManual lead, import, API, Sheets, Facebook, portals, microsite enquiry
Follow upCall / WhatsApp, scheduled follow-up, site visit, tasks, notes
BookConvert lead → booking (property, unit, agreement value)
EarnInvoice, mark agreement, payout received, revenue screens

2.2Product modules

The tenant sidebar is the module map. Items appear only if the user’s role allows it and the company’s plan includes that feature.

Dashboard

Welcome line, five KPIs (total leads, active leads, site visits, bookings, sales), sales pipeline by status, today’s tasks, and My Day (follow-ups and site visits due).

InSyte AI OS

Chat is shipped. The model can search leads, read today’s agenda, schedule or complete follow-ups and site visits, create or complete tasks, and add notes. Other tabs are visible and labelled as not ready. Access: permission ai.use and plan feature InSyte AI.

Leads

All leads table with search, filters, import, column editor, bulk assign / status / delete. Sub-views: Priority, Unassigned, Converted, Lost, Duplicates. Opening a lead uses a drawer (name, status, budget, property type, notes, documents, timeline, WhatsApp, follow-up, site visit, tasks).

Activities

Home for scheduled work. Follow-ups and site visits are separate lists with reschedule and complete. Site visits record type (fresh visit or revisit) and a property.

Tasks

Standalone task list plus tasks on a lead. Statuses: Pending → In progress → Complete, or Cancelled.

Properties

Project inventory (apartment, villa, plot, shop, office). Status, website visibility, optional public microsite. Microsite CMS sections: hero, highlights, about, configurations, amenities, visuals, location, developer, call to action.

Bookings

Create a booking from a converted (or converting) lead: property, unit, agreement value, date. Later: mark agreement, create invoice.

Revenue

Sales totals, invoices (edit, PDF, mark paid), payouts (mark paid). This is how commission is tracked in the product today.

Reports

Operational reports with export and print. Analytics adds velocity, aging, property-type performance, source and agent tables. Plan-gated: analytics, export, print.

Teams

Sales teams, members, archive. Performance view per team. Team Inbox is a header drawer (conversations, attachments), gated by the Team Inbox plan feature.

Automations

Workflows: trigger + conditions + actions, test run, on/off. Templates: WhatsApp / email / SMS copy with merge variables. Workflows apply to leads assigned to the current user unless the workflow is set otherwise in the editor.

Settings

Tabs: Profile, Company, Security, Users, Roles & Permissions, Domains, Integrations. Roles are switch-based permissions grouped by module.

Platform

Superadmin: dashboard, channel partners, plans. Revenue & Billing, Quotations, Integrations, Analytics, Utilities, and Settings in the platform sidebar are stub routes today.

2.5User journeys

1. Superadmin creates a channel partner

  1. Sign in at /platform/login.
  2. Open Channel Partners → create company (wizard: company details, admin user, plan).
  3. Partner appears on the list. Overview, users, subscription, and usage are available.
  4. The new admin signs in at /{slug}/login and lands on the dashboard.

2. Agent starts the day

  1. Sign in to the tenant CRM.
  2. Dashboard: My Day and today’s tasks.
  3. Open Priority leads, or ask InSyte AI OS “what is due today?”.
  4. On a lead: call or WhatsApp, log activity, complete or reschedule the follow-up.

3. Facebook or portal lead arrives

  1. Admin connects Facebook or copies a portal webhook in Settings → Integrations.
  2. A buyer submits a lead form on Meta or a portal.
  3. Webhook creates the lead with the right source.
  4. If a workflow is on for “lead created”, InSyte can add a task, a note, change status, or schedule a follow-up.
  5. The assigned agent sees the lead in the list and contacts them.

4. Google Sheet row becomes a lead

  1. Settings → Integrations → Google Sheets → add spreadsheet URL.
  2. Verify access, map columns (name, phone, and the other mappable fields).
  3. Connect. Sync now, or wait for the one-minute scheduler.
  4. New rows appear as leads. Pause stops further sync without deleting the connection.

5. Site visit to booking to payout

  1. On the lead, schedule a site visit (property + fresh visit or revisit + time).
  2. Complete the visit (outcome / notes as the form requires).
  3. Move through negotiation. Close as converted and create a booking (or create booking from Bookings).
  4. Mark agreement if needed. Create invoice. Download PDF.
  5. When commission is received, mark the payout paid. Revenue totals update.

6. Property page enquiry

  1. Add a property. Turn microsite on (plan must include microsites).
  2. Edit CMS sections and media.
  3. Share /{tenant}/projects/{slug} or the website domain URL.
  4. Buyer submits Enquire. A lead is created, throttled to 8 per minute per project.

This local Acme workspace had no properties, so there is no public microsite screenshot in this edition.

7. Ask InSyte AI OS to schedule a follow-up

  1. Open InSyte AI OS. Stay on Chat.
  2. Example: “Schedule a follow-up for Rahul tomorrow at 4pm.”
  3. The model calls search_leads / get_lead, then schedule_follow_up.
  4. The follow-up appears on the lead and in Follow-ups / My Day. Usage counts against the monthly AI message limit.

8. Admin sets a role

  1. Settings → Roles & Permissions → create or edit a role.
  2. Switch permissions by group (Leads, Activities, Revenue, and so on).
  3. Settings → Users → assign the role. An agent without settings.company will not see company or domain tabs.

9. Marketing visitor books a demo

  1. Open the public site.
  2. Submit Book demo or Start trial.
  3. The submission is stored centrally (LandingSubmission). It is not a tenant lead until someone onboards that company.
